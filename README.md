## 흐름
작성한 흐름을 세분화하면 다음과 같은 순서가 된다.

예측(Prediction): 이동(좌/우/하)이나 회전을 하기 전, **"다음 위치"**를 미리 계산한다.

판단(Validation): 그 위치가 벽에 부딪히는지, 혹은 바닥 블록(Static Board)과 겹치는지 체크한다.

반응(Action):

성공: 블록의 좌표를 실제로 업데이트한다.

충돌(바닥 방향): 블록을 그 자리에 **'착수(Lock)'**시킨다.

착수 후 처리 (The Cleanup):

게임 오버 체크: 새로 착수된 블록이 화면 최상단(y=0)을 벗어났거나, 생성되자마자 겹쳐 있다면 게임 종료다.

줄 삭제: 보드 배열을 한 줄씩 검사해서 None이 없는 줄을 찾는다.

중력: 삭제된 줄 위의 데이터를 한 칸씩 아래로 복사한다.

재시작: 다음 블록을 생성하고 1번으로 돌아간다.


### '중력' 구현 시 주의할 점

줄을 지우고 중력을 줄 때, 단순히 배열을 지우는 것보다 새로운 보드를 만든다는 느낌으로 처리하는 게 버그가 적다.

비어있는 새 보드(혹은 임시 벡터)를 준비한다.

기존 보드를 아래서부터 위로 훑는다.

"지워질 줄이 아닌" 줄들만 새 보드에 아래서부터 차곡차곡 쌓는다.

나머지 윗부분은 빈칸으로 채운다.

기존 보드를 이 새 보드로 교체한다.

### 보드와 스폰

**10x22 배열 설계**

생성 공간 확보: 블록이 y=0, 1 영역에서 생성되어 서서히 내려오게 할 수 있다. 사용자에게는 y=2부터만 보여준다.

게임 오버 판정: 블록이 바닥에 닿아 고정(Lock)되었는데, 블록의 일부가 여전히 y=0이나 y=1에 걸쳐 있다면? 그게 바로 게임 오버다.

인덱스 안전: 블록을 회전시킬 때 일시적으로 $y$값이 위로 튀더라도 22줄의 여유가 있으면 배열 범위를 벗어나서 프로그램이 죽는 일을 막아준다.
